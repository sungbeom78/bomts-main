BOMTS 운영 매뉴얼

공개 웹사이트·터널·Self-hosted 메일을 검증된 운영 절차와 함께 인수인계합니다.

BOMTS
이 매뉴얼은 BOMTS 공개 서비스의 현재 상태를 설명합니다. 웹사이트와 decision 서비스에 더해 Mailu가 외부 SMTP를 직접 수신합니다. 실제 호스트 구조와 비밀번호, 토큰, 개인키는 Public 매뉴얼에 기록하지 않습니다.

읽는 방법

세 역할이 같은 운영 상태를 봅니다

사용자www·decision 접속
→
운영자health·터널·백업 확인
→
개발자저장소·검사·매뉴얼 갱신
공개 코드는 bomts-main, 실제 호스트 설정과 원시 증거는 별도의 비공개 운영 보관소가 정본입니다.
일반 사용자는 공개 URL이 응답하는지만 확인합니다. 운영자는 로컬 원본과 터널을 나눠 점검하고, 개발자는 변경과 검증 기록을 남깁니다. 세 역할이 같은 증거를 보게 해 추측으로 상태를 판단하지 않도록 구성했습니다.

현재 상태

웹·터널·메일 수신이 운영 중입니다

PUBLIC WEBwww 200
DECISIONpublic 200
CLOUDFLAREDactive
MAIL INBOUND실수신
Mailbox와 외부 수신은 운영 중이며, 일반 발신과 외부 Webmail은 남은 작업을 완료한 뒤 개방합니다.
외부 TCP 25와 Mailu 배너를 확인했고 실제 Gmail 메시지가 founder Mailbox에 도착했습니다. 독립 계정과 로컬 Webmail·IMAP·POP3·Submission도 동작합니다. 다만 직접 발신이 Gmail 스팸으로 분류되어 SMTP relay가 필요하고, 외부 클라이언트 포트는 공유기 전달이 남았습니다.

1단계 — 컨테이너 상태를 확인합니다

project rootread-only
cd /project/bomts-main
docker compose ps
bomts_public_website · Up · healthy · loopback/LAN 3001→80
정상 기준: website가 healthy이고 공개 loopback과 내부 LAN 주소에 3001이 바인딩됩니다.
프로젝트 루트에서 Compose 상태를 확인합니다. 실제 출력에는 bomts_public_website가 healthy로 표시됐고 공개 터널용 loopback과 내부 접근용 LAN의 3001번이 컨테이너 80번으로 연결됐습니다. 컨테이너가 없거나 unhealthy라면 운영 장의 배포 절차부터 확인합니다.

항상 로컬 원본을 먼저 확인하고 공개 주소를 확인합니다. 실제 재실행 결과는 healthz 본문 ok와 공개 HTTP 200이었습니다. 로컬만 성공하면 터널 장을 보고, 로컬도 실패하면 웹사이트 또는 운영 장을 확인합니다.

장 목록

업무별 장에서 바로 시작합니다

🌐웹사이트페이지·배포·health🎓강의 QR 덱화면 전환·자료 추가🔗터널라우팅·검증·복구✉️메일계정·접속·백업·relay📚내부 매뉴얼LAN 메뉴·접근 통제🧩시스템 구성흐름·경계·정본🛠️운영·인수인계설치·백업·장애 대응
웹사이트 장은 공개 페이지를 운영하거나 내용을 바꿀 때 사용합니다. 터널 장은 로컬은 정상인데 공개 접속이 실패할 때 보고, 메일 장은 계정 사용, 외부 계정 가져오기, 백업, 발신 relay 상태를 설명합니다. 시스템 구성과 운영 장은 인수인계 시 함께 읽습니다.

제한 사항

현재 제한을 먼저 확인해야 오해가 없습니다

영역현재 제한다음 확인

수신 완료와 발신·외부 Webmail 완료를 구분해 운영합니다.
Mailu의 외부 수신과 Mailbox 저장은 확인됐습니다. 남은 항목은 발신 relay 제공자 계정, 공유기 클라이언트 포트 전달, 인증서 갱신 사용자의 linger 설정입니다. 각 항목은 완료 후 별도의 외부 시험으로 상태를 갱신합니다.
