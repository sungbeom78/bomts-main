시스템 구성

외부 edge, Mini PC 서비스, 저장소 정본과 운영 증거를 한 구조로 봅니다.

BOMTS
이 장은 BOMTS 공개 웹, 터널, 메일 시스템의 실행 위치와 데이터 흐름을 설명합니다. 공개 문서에는 논리 구조만 남기고 실제 호스트 경로, 주소, 자격 증명은 Private 인프라 저장소에서 관리합니다.

전체 구성

공개 HTTP는 터널로, SMTP는 Mailu로 들어옵니다

공개 HTTP 요청은 Cloudflare edge와 cloudflared를 거쳐 웹 또는 decision 서비스로 전달되고, 내부 운영자는 LAN 바인딩으로 웹 매뉴얼에 접근합니다. 메일 SMTP는 Cloudflare HTTP Tunnel을 통과하지 않고 DNS-only mail 호스트의 25번으로 직접 들어와 Mailu에 저장됩니다. 발신만 전달 품질 때문에 외부 SMTP relay를 추가할 예정입니다.

데이터 흐름 · 웹

www 요청은 다섯 단계로 정적 파일에 도달합니다

  1. DNSwww.bomts.net
  2. CloudflareHTTPS edge
  3. cloudflaredingress match
  4. Nginx3001→80
  5. site fileHTML·asset 응답
관측 결과: local health ok/200, public 200.
www 요청은 DNS와 Cloudflare HTTPS 처리 후 tunnel ingress에서 3001번 원본을 선택합니다. Nginx가 URL을 site 파일에 매핑해 정적 응답을 반환합니다. 로컬과 공개 결과를 함께 보면 이 전체 흐름의 어느 앞부분까지 정상인지 판단할 수 있습니다.

데이터 흐름 · Decision

decision 요청은 같은 터널에서 9002 원본으로 분기합니다

  1. 사용자decision.bomts.net
  2. Cloudflare공개 HTTPS
  3. ingresshostname 선택
  4. origin127.0.0.1:9002
  5. 응답local·public 200
검사 스크립트는 잘못된 http://:127... 값이 남아 있지 않은지도 확인합니다.
decision은 www와 같은 cloudflared 프로세스를 사용하지만 별도 hostname 규칙으로 9002번에 연결됩니다. 과거 잘못된 origin 문자열을 복구했기 때문에 검사 스크립트가 올바른 값과 잘못된 값의 부재를 모두 확인합니다. 현재 로컬과 공개 응답은 200입니다.

데이터 흐름 · 메일

메일 수신은 MX에서 사용자 Mailbox까지 직접 흐릅니다

  1. 외부 MTAMX 조회
  2. Mailu SMTPTCP 25
  3. 필터spam·virus
  4. 사용자 판정domain·account
  5. Mailboxpersistent storage
실제 Gmail 메시지가 이 경로로 founder Mailbox에 저장됐습니다.
외부 발신 서버는 MX를 조회해 Mailu SMTP에 접속합니다. 수신 주소가 등록된 독립 사용자 또는 alias인지 확인하고 스팸·바이러스 검사를 거친 뒤 사용자별 Maildir에 기록합니다. 외부 수신 시험으로 이 전체 경로를 확인했습니다.

Mailbox의 물리 경로와 계정 비밀은 Public 저장소에 기록하지 않습니다.
BOMTS 메인 저장소는 업무 데이터를 직접 소유하지 않아 external 입장입니다. AI 서비스의 모델 정본은 공개 dev-ai 저장소의 db/model.json이고, 의사결정 서비스의 현재 실제 SQLite 스키마 정본은 bomts-decision의 Prisma schema입니다. Mailu의 데이터 종류와 백업 단위는 Private bomts-infra의 data-map이 정본이며, 실제 메일 내용과 계정 비밀은 호스트 저장소에만 둡니다.
