설정 · 2 / 2

비밀 값은 매뉴얼과 evidence 경계 밖에 둡니다

Public 기록 가능

  • 공개 URL과 기능 설명
  • placeholder 환경 변수명
  • 일반화한 구성도
  • 비밀 없는 검사 결과

Private 또는 저장 금지

  • 실제 IP·터널·방화벽 설정
  • 메일·DB password
  • DKIM private key
  • Cloudflare API token
Git history에 들어간 비밀은 삭제만 하지 말고 즉시 폐기·재발급합니다.
Public에는 사용자가 알아야 할 기능과 placeholder만 둡니다. 실제 서버 토폴로지는 bomts-infra로 분리하고 인증 값은 그 Private 저장소에도 plaintext로 넣지 않습니다. 비밀이 커밋된 적이 있으면 현재 파일에서 지워도 과거 commit에서 읽을 수 있으므로 먼저 credential을 회전합니다.

인수인계

인수인계는 실행 상태와 대기 항목을 함께 넘깁니다

www local·public 200 확인
decision local·public 200 확인
cloudflared validate OK·active
config backup 위치 확인
Mailu health·SMTP 25 확인
최근 일관 백업·복구 시험 확인
outbound relay·외부 client port 인계
비밀이 evidence에 없는지 확인
Git과 task 상태 확인
인수인계 시 정상 서비스뿐 아니라 아직 끝나지 않은 작업을 같이 전달합니다. Mailu는 실제 외부 수신과 복구 시험이 완료됐고, 발신 relay와 외부 Webmail·클라이언트 포트가 다음 행동입니다. 비밀 값이 문서와 evidence에 포함되지 않았는지도 마지막으로 확인합니다.

개발 작업 절차는 여러 프로젝트가 함께 쓰는 프레임워크 매뉴얼이 정본입니다. Task의 생성과 검증, 완료 방법은 task 장을 열어 확인합니다. BOMTS에만 적용되는 더 엄격한 서브모듈 규칙은 프로젝트 전용 rules 파일을 먼저 읽습니다.
