BOMTS 메일 운영

메일함과 계정은 자체 운영하고, 인터넷 발신 품질은 외부 SMTP relay로 보완합니다.

MAIL
BOMTS 메일은 Mailu 2024.06으로 구축했습니다. 인터넷 TCP 25 수신, 독립 사용자, Webmail, IMAP, POP3, Submission, 백업과 복구 시험까지 확인했습니다. 외부 메일 수신은 운영 가능하며, 발신은 가정용 회선의 PTR 부재 때문에 relay 계정 연결이 남아 있습니다.

배포 버전은 Mailu 2024.06이며 이미지 버전은 운영 변경 절차로 올립니다.
Mini PC는 네 코어와 15GiB 메모리를 갖지만 다른 BOMTS 서비스도 함께 실행합니다. Mailu는 독립 계정, quota, 다중 도메인, 표준 프로토콜, Roundcube, 외부 계정 가져오기를 하나의 Compose로 제공해 가장 적합했습니다. mailcow는 더 무겁고 Stalwart는 Webmail을 별도 통합해야 합니다.

외부 사용

  • DNS edge
  • 향후 outbound relay

외부 메일 서버가 mail.bomts.net의 25번으로 전달하면 Mailu가 수신 정책과 스팸·바이러스 검사를 적용하고 사용자 Maildir에 저장합니다. 메일함과 계정은 외부 제공자에 두지 않습니다. 향후 outbound relay를 연결해도 relay는 발송 경로만 맡고 Mailbox 데이터는 Mini PC에 남습니다.

비밀번호는 Git 밖에서 관리합니다. 오작동한 브라우저 유출 횟수 검사는 비활성화했고 운영자가 고유한 무작위 비밀번호와 교체 주기를 관리합니다. Catch-all은 사용하지 않습니다.
founder, ott.disney, ott.netflix는 alias가 아니라 실제 사용자입니다. 세 사용자는 각각 고유 암호 hash, quota, Maildir을 가지며 교차 로그인이나 교차 조회가 되지 않습니다. 로컬 Submission으로 각 사용자에게 고유 제목을 전달한 뒤 IMAP에서 자신에게 온 제목만 보이는 것으로 격리를 확인했습니다.

외부 발신은 relay 계정과 도메인 인증을 연결한 뒤 Gmail·Naver·Outlook에서 다시 합격해야 합니다.
직접 발송 시험은 Gmail 서버가 수락했고 SPF, DKIM, DMARC도 모두 통과했지만 스팸으로 분류됐습니다. 현재 공인 IP에 PTR이 없어 정상적인 대화형 메일 운영 품질을 기대하기 어렵습니다. 따라서 수신은 직접 유지하고 발신만 SMTP2GO 같은 인증 relay로 전환하는 것이 현재 판정입니다.

자동 전달

사용자별 전달 목록을 웹에서 관리합니다

  1. 사용자 선택Mailu Admin
  2. Auto-forward활성화
  3. Destination쉼표 목록
  4. Keep copy원본 보관 선택
한 Mailbox에 도착한 메일을 여러 외부 주소로 전달하면서 Mini PC Mailbox에도 원본을 남길 수 있습니다.
Mailu의 사용자 설정에는 기본 Auto-forward 기능이 있습니다. Destination은 여러 이메일 주소를 쉼표로 받으며, Keep a copy를 켜면 전달 후에도 원본 Mailbox에 메일이 남습니다. 계정별로 서로 다른 목록을 저장할 수 있습니다. 전달 대상 주소와 외부 계정 비밀번호는 운영 DB에만 저장하고 Git이나 evidence에는 기록하지 않습니다.

수신 서비스는 운영 중입니다. 남은 항목을 끝내기 전에는 외부 Webmail과 안정적 발신을 완료로 표시하지 않습니다.
현재 실제 외부 수신은 가능하지만 사용자 클라이언트용 포트는 공유기 전달이 남았습니다. 발신 relay는 제공자 계정과 자격 증명이 필요합니다. 인증서 타이머는 활성화했지만 로그아웃과 재부팅 뒤에도 사용자 서비스를 살리려면 관리자가 linger를 한 번 활성화해야 합니다. 이 세 항목은 Mailbox 데이터의 정상 여부와 분리해서 운영합니다.
