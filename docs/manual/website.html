공개 웹사이트

정적 페이지를 Nginx 컨테이너로 제공하고 Cloudflare Tunnel로 공개합니다.

BOMTS
이 장은 www.bomts.net의 사용자 경로와 운영 절차를 설명합니다. 저장소의 site 디렉터리가 콘텐츠 정본이고 Nginx 컨테이너는 이를 읽기 전용으로 제공합니다. 공개 오류는 로컬 원본과 터널을 나누어 진단합니다.

사용 흐름

공개 요청은 loopback으로, 내부 문서는 LAN으로 들어옵니다

공개

Cloudflare → 127.0.0.1:3001

일반 사이트만 제공

내부

LAN → <LAN_IP>:3001

매뉴얼·관리 메뉴 추가
  1. 브라우저공개 또는 LAN
  2. Nginx요청 경로 판정
  3. site/공개 화면
  4. manual/내부만 허용
외부 사용자는 HTTPS로 Cloudflare에 접속하고 cloudflared가 요청을 loopback 3001번으로 전달합니다. 내부 사용자는 별도 LAN 바인딩으로 같은 사이트에 접속합니다. Nginx는 Cloudflare 헤더와 사설 주소를 함께 보고 내부 문서 접근을 판정합니다.

Nginx의 healthz는 정적 콘텐츠와 별도로 200과 ok를 반환합니다. 이 결과가 실패하면 Cloudflare보다 먼저 컨테이너와 포트를 복구해야 합니다. 공개 200까지 확인되면 원본과 터널 경로가 모두 정상입니다.
