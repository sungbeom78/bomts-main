Cloudflare Tunnel

공개 호스트 이름을 Mini PC의 loopback 서비스로 안전하게 연결합니다.

BOMTS
이 장은 cloudflared 서비스와 www·decision 라우팅을 점검하는 방법을 설명합니다. 설정 정본은 시스템의 /etc/cloudflared/config.yml이며 저장소에는 비밀 값을 복사하지 않습니다. 변경이 필요하면 백업과 검증을 먼저 수행합니다.

cloudflared는 공개 호스트 이름을 각 로컬 서비스에 연결합니다. 이번 증거 수집에서 설정 검증은 OK, systemd 서비스는 active였고 www와 decision이 모두 200을 반환했습니다. 메일 SMTP 25는 이 HTTP 터널의 대체 경로가 아닙니다.

점검 · 1 / 3

설정을 바꾸지 않고 ingress 문법을 검증합니다

cloudflaredread-only
cloudflared tunnel --config /etc/cloudflared/config.yml ingress validate
Validating rules from /etc/cloudflared/config.yml
OK
이 명령은 토큰이나 ingress 값을 출력하지 않고 유효성만 확인합니다.
검증 명령에서 config 옵션은 tunnel 하위 명령 앞에 둡니다. 실제 재실행 결과 설치된 설정 파일을 읽어 OK를 반환했습니다. 매뉴얼과 evidence에는 터널 토큰이나 전체 설정 내용을 남기지 않습니다.

점검 · 2 / 3

decision 전용 검사로 로컬·공개·백업을 함께 확인합니다

repository scriptactual output
./scripts/check-decision-tunnel.sh
Validating rules ... OK

저장소의 검사 스크립트는 설정 문법, 서비스 상태, 올바른 9002 원본, 로컬 응답, 공개 응답과 백업 파일을 한 번에 확인합니다. 이번 재실행에서 모든 항목이 성공했습니다. 실패하면 스크립트가 멈춘 지점이 바로 조사할 구간입니다.

점검 · 3 / 3

변경은 백업·후보 검증·재시작·공개 확인 순서입니다

  1. 백업timestamp .bak
  2. 후보 수정임시 파일 한 값
  3. 검증candidate + installed
  4. 재시작systemctl
  5. 확인local·public 200
시스템 설정 변경은 sudo scripts/fix-decision-tunnel.sh처럼 승인된 운영 작업에서만 실행합니다.
복구 스크립트는 원본을 바로 편집하지 않고 먼저 timestamp 백업과 임시 후보를 만듭니다. 후보와 설치된 설정을 각각 검증한 뒤에만 cloudflared를 재시작합니다. 공개 확인이 실패하면 trap이 백업을 복원하도록 설계돼 있습니다.

내부 처리

검사와 복구가 같은 설정을 다른 권한으로 다룹니다

  1. 읽기 검사check-decision-tunnel.sh일반 사용자
  2. 시스템 정본/etc/cloudflared/config.ymlroot 소유
  3. 안전 복구fix-decision-tunnel.shroot·backup·rollback
  4. 서비스cloudflared.servicesystemd
일상 점검은 읽기 전용 스크립트로 수행하고 변경이 필요한 경우에만 root 전용 복구 스크립트를 사용합니다. 두 스크립트가 같은 config 경로와 decision 원본을 검사해 점검과 변경 기준이 어긋나지 않게 합니다. systemd는 검증된 설정을 실제 프로세스에 적용합니다.

보안 경계

비밀은 시스템에 두고 저장소에는 위치와 검사만 남깁니다

저장소에 기록

  • 설정 경로
  • 백업 경로
  • 검증 명령과 상태
  • 공개 HTTP 결과

저장소에 금지

  • 터널 토큰
  • credentials JSON 내용
  • Cloudflare API token
  • 개인키와 비밀번호
evidence에는 active · validate OK · HTTP 200만 남깁니다.
운영자가 알아야 할 경로와 확인 결과는 문서화하지만 인증 값 자체는 시스템에만 둡니다. 설정 전체를 출력하면 토큰이나 내부 주소가 섞일 수 있으므로 validate와 상태 명령을 사용합니다. 유출 가능성이 있는 출력은 저장 전에 별표로 가리고 다시 확인합니다.
