강의 QR 덱

프로젝터에 QR 자료를 한 장씩 크게 띄우고, 같은 주소를 수강생과 공유합니다.

LECTURE
이 장은 lecture.bomts.net의 사용법과 확장 방법을 설명합니다. 강사는 키보드나 화면 클릭으로 QR을 한 장씩 넘기고 수강생은 휴대전화 카메라 또는 QR 이미지 클릭으로 자료를 엽니다. 첫 화면의 준비 매뉴얼은 큰 다운로드 버튼으로 바로 받을 수 있습니다.

브라우저에서 lecture.bomts.net을 열면 첫 번째 QR이 선택됩니다. 발표 화면에는 클릭 가능한 QR과 준비 매뉴얼 다운로드 버튼이 나란히 보이며, 직접 링크도 아래에 남아 있습니다. 특정 화면으로 바로 시작하려면 주소 끝의 번호 해시를 사용하며 첫 화면은 #1입니다.

  1. 둘째 화면#2로 이동
  2. 파일 받기QR 스캔 또는 링크 클릭
  3. 다운로드 폴더prompt-card-D2.html 확인
  4. 로컬 실행파일을 브라우저로 열기
서버 URL에서는 HTML이 실행되지 않고 항상 첨부 파일로 내려옵니다.
둘째 화면의 QR과 아래 링크는 같은 HTML 파일을 다운로드합니다. 응답은 attachment와 application/octet-stream으로 강제해 서버 주소에서 스크립트가 실행되지 않습니다. 다운로드 폴더에 저장된 파일을 브라우저로 열면 로컬 저장소도 서버 페이지와 분리됩니다.

프롬프트 카드 URL에는 Nginx 정확 일치 규칙을 적용합니다. 응답 형식과 attachment 헤더가 브라우저 다운로드를 강제하고, sandbox 헤더가 서버 실행을 한 번 더 제한합니다. 다운로드된 파일에는 HTTP 응답 헤더가 남지 않으므로 사용자가 로컬에서 열면 원래 기능을 사용할 수 있습니다.

장애 대응

QR·화면·공개 경로를 순서대로 나누어 확인합니다

증상원인 후보조치
QR 인식 실패화면 밝기·QR 이미지 오류다운로드 URL과 QR 내용을 대조
HTML이 화면에서 열림attachment 규칙 미적용Content-Disposition·Content-Type 확인
다운로드 후 상태 이상기존 로컬 저장 상태다른 폴더·브라우저 프로필에서 실행
공개 404·502DNS·Tunnel ingress·컨테이너로컬 Host 응답부터 단계별 확인
프롬프트 카드는 서버에서 실행하지 말고 내려받은 파일을 직접 엽니다.
QR이 읽히지 않으면 공개 다운로드 URL과 QR 생성 값을 대조합니다. 직접 URL에서 HTML 화면이 보인다면 Nginx의 exact location과 attachment 헤더가 빠진 것입니다. 내려받은 파일의 상태가 예상과 다르면 기존 로컬 저장소 영향을 피하도록 다른 폴더나 새 브라우저 프로필에서 실행합니다.
