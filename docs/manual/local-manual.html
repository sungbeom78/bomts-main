내부 매뉴얼

LAN 접속자에게만 홈페이지 메뉴와 운영 문서를 제공합니다.

BOMTS
이 장은 홈페이지에 포함된 내부 전용 매뉴얼 기능을 설명합니다. 같은 웹 이미지가 공개 경로와 LAN 경로를 제공하지만 매뉴얼과 관리 메뉴는 내부 요청에서만 만들어집니다. 공개 사용자는 메뉴와 문서 경로를 볼 수 없습니다.

전체 흐름

공개 경로와 내부 경로가 같은 사이트에서 갈라집니다

내부 LAN

http://<LAN_IP>:3001

내부 판정 → 매뉴얼·관리 메뉴 표시 → 문서 200

공개 인터넷

https://www.bomts.net

Cloudflare 헤더 감지 → 메뉴 미표시 → 문서 404
  1. 브라우저홈페이지 접속
  2. context내부 여부 확인
  3. 메뉴조건부 생성
  4. 문서내부 요청만 응답
공개 사용자는 기존 주소와 화면을 그대로 사용합니다. 내부 사용자는 Mini PC의 LAN 주소와 3001번으로 접속하고 서버가 내부 요청임을 확인합니다. 메뉴 숨김만으로 보호하지 않고 Nginx가 문서 URL도 다시 검사합니다.

내부 허용 · 공개 거부
JavaScript 메뉴가 보이지 않는 것과 별개로 Nginx가 문서 요청을 직접 거부합니다.
테스트 이미지에서 내부 context와 두 문서 경로는 200을 반환했습니다. Cloudflare 요청 헤더를 포함한 같은 요청은 모두 404였습니다. 브라우저 메뉴를 우회해 URL을 직접 입력해도 공개 경로에서는 문서를 받을 수 없습니다.

내부 처리

Nginx 판정과 JavaScript 메뉴가 두 단계로 동작합니다

  1. 요청 분류Cloudflare 헤더·사설 주소nginx/default.conf
  2. context내부 요청만 JSON 200/local/context.json
  3. 메뉴 생성두 링크를 DOM에 추가site/assets/main.js
  4. 문서 방어매 요청을 다시 검사location ^~ /manual/
파일역할
Dockerfile검증된 매뉴얼을 웹 이미지에 포함
docker-compose.ymlloopback과 LAN 주소에 각각 3001 바인딩
Nginx는 Cloudflare 연결 헤더가 없는 사설 네트워크 요청만 내부로 판정합니다. JavaScript는 context 응답이 성공할 때만 메뉴 링크를 만듭니다. 문서 location도 같은 판정을 수행하므로 화면 표시 로직이 접근 통제의 유일한 수단이 되지 않습니다.

공개 문서가 200이면 기능 정상으로 간주하지 않고 접근 통제 장애로 처리합니다.
내부 홈 접속, context 응답, 메뉴 표시, 문서 응답을 순서대로 확인합니다. 특정 단계부터 실패하면 해당 파일과 컨테이너 상태만 점검할 수 있습니다. 공개 경로에서 문서가 열리는 경우에는 보안 경계가 깨진 것이므로 즉시 롤백합니다.
