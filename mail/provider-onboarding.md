# Zoho Mail onboarding runbook

Status: deprecated. Zoho onboarding was stopped when BOMTS moved mailbox hosting to Mailu. Keep this file only as historical provider-migration guidance; current accounts and operations are defined in `address-policy.yaml` and `docs/mail-operations.md`.

## Why this path

The audited host has outbound TCP 25 connectivity but no public PTR record, and inbound TCP 25/port forwarding are unverified. A hosted mailbox is the shortest reliable route to a working `founder@bomts.net` while preserving future migration options.

Zoho's official administration documentation supports adding an existing custom domain, separate users and aliases, and verification of MX, SPF, DKIM, and DMARC. Values vary by Zoho data center, so the Admin Console is the only source for production DNS values.

## 1. Create the organization

1. Create or sign in to a Zoho Mail administrator account owned by the BOMTS founder.
2. Select a current plan supporting the needed independent users and client access.
3. Add the existing domain `bomts.net`.
4. Copy the domain verification TXT or CNAME value shown by Zoho.

Do not store the administrator password, recovery codes, verification token, or API token in this repository.

## 2. Back up DNS

Before any DNS change, export the `bomts.net` zone from Cloudflare or capture every record and proxy state. Record the export timestamp in `docs/application-readiness.md`.

## 3. Verify domain ownership

Add the exact verification record generated by Zoho. Wait for propagation and use the Zoho Admin Console Verify action. This step should not alter current website routing.

## 4. Create accounts and aliases

For a future provider migration, reproduce every independent mailbox currently defined in `address-policy.yaml`:

- `founder@bomts.net`
- `admin@bomts.net`
- `ai.claude@bomts.net`
- `ai.openai@bomts.net`
- `ott.disney@bomts.net`
- `ott.netflix@bomts.net`
- `infra.cloudflare@bomts.net`

Then create `contact@bomts.net -> founder@bomts.net` and `abuse@bomts.net -> admin@bomts.net`. Keep catch-all disabled and preserve separate credentials and storage for every mailbox.

## 5. Publish delivery records

Use only values displayed for the selected Zoho data center:

1. Replace any previous mail-provider MX records with the Zoho MX set and priorities.
2. Publish one apex SPF TXT record. Merge legitimate senders into one SPF policy; never publish two SPF records.
3. Generate a 2048-bit DKIM selector in the Zoho Admin Console and publish its TXT value.
4. Verify and enable the DKIM selector in Zoho.
5. Review the existing `_dmarc` record. Replace the single existing record with an intentional monitoring policy and an owned reporting mailbox before tightening enforcement.

## 6. Test and record evidence

Run:

```bash
./scripts/audit-mail.sh bomts.net
```

Then perform the Gmail, Naver, and Outlook inbound/outbound matrix described in `docs/mail-operations.md`. Preserve redacted headers showing SPF, DKIM, and DMARC results. Test a verification email, one-time code, and password reset at the founder address.

## 7. OTT isolation

Sign out of founder Webmail, sign in as the OTT user, and verify that only the OTT mailbox is visible. Test the independent mailbox `ott.disney@bomts.net`, then log out. Do not share the founder credential.

## Rollback

If mail delivery fails after MX migration, restore the DNS export and previous MX/SPF/DMARC state. DNS rollback does not recover messages accepted by the new provider, so keep the Zoho organization active until delivery logs are reconciled.
